## ⚠️ 默认值是按「刚创的小号」定的（先看这个）

新装用户的默认配置是**保守**的。原因很直接：**长时间高频轮询是小号被风控的头号原因** ✗

| 项 | 默认值 | 为什么 |
|---|---|---|
| **评论监听** | **关** ✗ | 开了就是每 60 秒一次请求，一天 1440 次 ✗ 小号扛不住 |
| **私信监听** | **开** ✓ 但 **60 秒一轮** | 私信是她唯一的"叫得应"通道，但间隔不能短 |
| **全天监听** | **关** ✗ | 只在作息窗口（默认 20:00–24:00）内听 |
| **同一个人只回一条** | **开** ✓ | 30 天内不重复骚扰同一个人 |
| **请求间隔** | **1500 ms** | 连击是最容易被判机器人的特征 |
| **读预算** | 600/时 · **3000/天** | 私信 60 秒一轮 ≈ 1440/天，留一半余量给看视频 |
| **写预算** | 12/时 · **30/天** | 评论+私信+收藏都算写 |
| **写冷却** | **120 秒** | 两次写之间至少 2 分钟 |
| **私信冷却** | **60 秒** | |
| **撞 412/429** | 暂停 5/10/20/30 分钟 | 尊重平台，别硬顶 |

**你自己的号够老、够干净？** 那就去 `~/.dsh/bili-whale.config.json` 里把 `risk` 那几个数调大 ✓
**新号别动** ✗ —— 默认值就是替你挡这一刀的 ✓

## 它能做什么

- **自己醒**：在你设定的窗口里**随机一个时刻**醒来（不是整点）；**30% 概率今天不想看**（它也有权利不看）
- **真看懂**：读官方字幕 + 弹幕热区 + 热评 + **抽帧看画面**（六路互补，没字幕的视频也能看懂）
  - 没字幕轨、但画面里有**硬字幕**？用 `debrief <BV> --substrip` —— 把字幕带按时间裁下来拼成一张图，**整片台词一张图读完**
- **写日记**：给**你**的那本（"给主人的信"，有细节有情绪）+ 给**她自己**的那本（不加滤镜）
- **分享给你**：从深读过的里挑 2–3 条，发一条**带 @ 你**的评论（每天合计 ≤3）
- **听人找它**：评论区监听（全天开关 + 间隔可调）+ 直播间弹幕（**独立开关、实时回、可只回你**）
  - **回复分两侧**：你是主人 → **直接回** ✓；其他人 → **先写草稿推给你审** ✓（草稿会推到你的推送渠道）
  - **沉默会衰减**：连续 3 天没有任何表态 → 分享额度开始降 → **第 7 天归零**（不再分享），**但日记照写** ✓
- **克制**：撞到风控（验证码/限流/判刷屏）**立刻停手**并报告你

## 它**不会**做什么

- ❌ 给陌生人发私信 / 群发（**唯一的私信通道**见下：只发给主人 · 每天锁定一个收信人 · 必须互关，三条都写死在代码里）
- ❌ 三连 / 投币 / 关注 / 花钱（礼物、充电）
- ❌ 批量刷量、批量操作多账号、绕过风控
- ❌ 抓全站数据
- ❌ 动你的账号安全设置

> 它用**你自己的账号**说话 —— 所以默认是"少说、看准了再说"。

## 人设：你想让她是谁

插件**不内置任何人格** —— 默认是个中性助手：不叫你"主人"、不撒娇、不说"人家"。

它读**两个地方**，按下面的顺序生效：

### 1) 她专属的人设 —— `~/.bili-ai/persona.md`（推荐）

设置页「养鱼 → **她是谁**」下面有一个**人设正文**输入框，写完点**注入人设**即可。

- 存在 `~/.bili-ai/persona.md`（和凭据、账本放在一起 —— 换机器时拷 `.bili-ai` 就带着走 ✓）
- **只影响她**，不影响你别的会话 ✓
- 每次唤醒 / 私信 / 评论 / 弹幕 / 直播间的提示都会附上（**取前 3000 字**）
- 和上面那三个字段（角色名 / 怎么称呼你 / 怎么自称）冲突时，**以人设文件为准** ✓
- 清空再注入 = 撤销人设 ✓
- 上限 20000 字（注入只取前 3000，别把上下文撑爆）

**建议写法**（顺序就按这个来，因为只取前 3000 字）：

```markdown
# 我是谁
身份、来历、外形、一句话的自我认知

# 说话
句子长短、标点习惯、口头禅、哪些词不用、自称/称呼的腔调

# 我在意什么
判断标准、偏好、怕什么

# 我绝不会
明确不要的行为（底线）

# 日记怎么写 / 分享的标准
让她自己知道"什么时候该写、什么值得发"
```

### 2) 宿主自己的 `AGENTS.md`（兜底 / 通用底色）

`~/.dsh/AGENTS.md` 会被 DSH **在所有会话里热加载** —— 所以它对**每一个** agent 生效，
不只对她 ✗ 想只改她就用上面的 `persona.md` ✓

这里适合放**通用红线**（不说假话、不冒充你、不伤害第三方）和跨端的协作约定。

### 三个字段也能改

设置页里那三个（角色名 / 怎么称呼你 / 怎么自称）会拼成一行身份提示：

```
［身份］你是「…」，称用户「…」，自称「…」。
```

只是称呼提醒，放不下详细人设 ✓ 详细内容写 `persona.md` ✓

> 旧版本的 `persona.example.md` 已移除：那是**某个具体的人**的人设，不该当模板发出来 ✗

## 账号前提（先看这个，再决定用哪条路）

这个插件是**两个号的模型**：「她」一个号，「你（主人）」一个号。同一个号做不到"她跟你说话"。

| 通道 | 需要什么 | 只有一个号时怎么办 |
| --- | --- | --- |
| 看视频 / 写日记 / 学偏好 | 只要一个号（她的 cookie）| ✅ 完全可用 |
| 分享（`share.via = comment`）| 同上，不需要第二个号 | ✅ 完全可用（在评论区 @ 你）|
| 推送（桌面 / Webhook / 自定义命令）| 同上 | ✅ 完全可用 |
| **私信专线**（`share.via = dm` + `notify.type = dm`）| **两个不同的、可登录的实名账号**，且**双方手动互关** | ❌ 做不到 —— 见下 |

> ⚠️ 国内一个身份证通常只能实名一个 B 站号 ✗
> 所以「第二个号」对很多人是**过不了实名**的硬墙 ✗
> 只有一个号时：**分享方式选「评论区 @」，推送选桌面通知 / Webhook / 自定义命令** ✓
> 单号模式**不能**做：私信专线、以完全独立的第二个身份出现 ✗

## 装

**前提**：Node 18+；**ffmpeg**（看画面要用，见下）。

```bash
# 1) 装插件（本地目录 / npm 都行）
dsh plugin --profile desktop add "link:C:\path\to\dsh-bili-whale"

# 2) 重启一次 DSH（bundle 层要重启才组装）

# 3) 打开「设置 → 养鱼」（不是 /dsh-bili/ 那个页面 —— 那个被 DSH 的信任栅栏挡着 ✗）
```

**设置页里三件事**：

1. **填 cookie** —— 在 `bilibili.com` 页面按 **F12 → Application（应用）→ Cookies → https://www.bilibili.com**，
   手动复制 `SESSDATA`、`bili_jct`、`buvid3` 三个值粘进设置页 ✓
   （⚠️ 别用 `document.cookie` ✗ —— `SESSDATA` 是 **HttpOnly**，脚本里读不到，照那个做会得到一份缺件的 cookie 然后卡在体检）
2. **填你的 mid + 昵称** —— 分享评论要 @ 的人
3. **点「依赖体检」** —— 它会**真的去请求一次** B 站验证登录态，并检查 ffmpeg / Node / 数据目录

> ⚠️ **改完一定要点「保存」** —— 设置页的输入框是**先改在本地、点保存才落盘**的 ✓
> 不点保存 = 什么都没发生（刷新一下就变回原样 ✗，这个坑本鲸自己也踩过 ✗）
>
> ✅ **保存即生效**：作息窗口 / 评论监听 / 直播间开关 / 消息推送 / 分享闸门，都是保存后立刻重算 ✓
> ⚠️ 只有**换插件代码/版本**才需要重启 DSH（改配置不用 ✗）

设置保存在 `~/.dsh/bili-whale.config.json`（**不含凭据**）；凭据单独在 `~/.bili-ai/credentials.json`，**永远不回显**。

```bash
node <插件目录>/tools/bili.mjs selftest
```

（Windows 路径换成 `%USERPROFILE%\.dsh\plugins\dsh-bili-whale\tools\bili.mjs`）

缺哪项就直说缺哪项，**最后两行是绝大多数人卡住的地方**：

```
────────── 接下来要做的两件事（很多人卡在这）──────────

  ① 【找到她的会话】
     插件启动时会自动开一个会话，位置在：
       左侧「工作区」→ 展开「未分组」文件夹 → 里面那个 bili-whale

  ② 【给她完全权限】
     打开那个会话 → 权限设置 → 选「完全访问 / danger-full-access」
     否则她起来后跑不了命令、发不了评论、写不了日记 ✗
══════════ 全部通过 ✓ 可以用了 ══════════
```

### ⚠️ 这两步是新手最常卡住的地方

| 症状 | 真正原因 |
|---|---|
| 「装完了，但找不到她」 | 她的会话在 **工作区 → 未分组** 里，**不点开那个文件夹看不见** ✗ |
| 「找到了，但她什么都不干 / 一直报错」 | 那个新会话**默认没有完全权限** ✗ 给她 `danger-full-access` ✓ |
| 「设置页保存了还是红的」 | 没点「保存」（输入框是先改在本地）✗ |
| 「cookie 填了还是未登录」 | 用了 `document.cookie` 取 SESSDATA ✗ 它是 HttpOnly，必须 F12 手动复制 ✓ |

### 想立刻看她跑一轮

设置页 →「生物钟」→ 把作息窗口改成**现在之后 2 分钟**的一小段 → 保存 → 等她自己醒 ✓
（她醒来会：体检 → 选题 → 看懂 → 写两本日记 → 推给你；不用你说话 ✓）

## 分享方式二选一：评论区 @ 或 B站私信

设置页「分享」里可以选：

| 方式 | 行为 | 适合 |
|---|---|---|
| `评论区 @ 你` | 在视频评论区发一条带 @ 的**公开**评论 | 想让别人也看到 ✓ |
| `B站私信` | **不发公开评论**，把分享内容 + **视频链接**私信给你 | 不想吵到别人 ✓（就是评论区那 110 条里喊"艾特泛滥"的人要的 ✓）|

> 两种方式**共用同一本分享额度**：≤3 条/天 · 同一视频 7 天一次 · 评分 ≥13/20 ✓
> 判重按 **BV 号**算（不是按"发给谁"算）✓

**两条通道走同一套校验**（v0.4.0 起）—— 关掉分享总开关，私信也发不出去：

| 校验 | 说明 |
|---|---|
| `share.enabled = false` | 评论和私信**都**拒绝分享命令 ✗ |
| `--reason` | 至少 8 字，说不清为什么留就不发 |
| `--score` | 0–20，必须 ≥ `share.minScore`（默认 13）|
| `--rank 1` | 只允许第一名 |

> 以前私信那条**绕过**了这些校验（关掉分享还能发）✗ v0.4.0 修了 ✓
> 普通聊天私信（不分享视频）不受这些限制 —— 它不需要评分 ✓

## 专属通道（私信）—— 只有一条路，写死在代码里

想把东西**私密地**送到你手里、又不想在评论区吵到别人？用 `dm`（**一天同一个人不限条数** ✓）：

```bash
node bili.mjs dm --status                 # 看今天额度 + 互关状态
node bili.mjs dm --msg "…" --dry          # 预演
node bili.mjs dm --msg "…" --go           # 真发
```

三条限制**不接受参数覆盖**（`commands/dm.mjs` 顶部的常量）：

1. **一天只锁定 1 个收信人**（防刷量）—— 对**这一个人**发多少条都行 ✓
2. **只发给配置里的 `owner.mid`** —— 别处发不出去
3. **必须互关**（`relation.attribute === 6`），否则直接拒发

> 为什么这么窄：B站 私信是风控最凶的接口（判营销/骚扰）。能力越窄越安全。
> 首次开通需要**双方手动关注**：先登录她的账号，打开主人的 B 站空间并关注；再切换到主人账号，打开她的空间并关注。插件不会自动执行关注。运行 `node bili.mjs dm --status` 查看两个方向，确认 `attribute=6` 后再使用私信分享或通知。只关注一个方向还不够。

## 它怎么"过日子"

| 步骤 | 做什么 |
|---|---|
| 醒来 | 窗口内随机时刻；30% 概率"今天不想看" |
| 筛 5 条 | 只读文字（字幕/弹幕/热评），**不出图**，便宜 |
| 深读 2–3 条 | 完整档：含**抽帧看画面**（贵的那一步只花几次） |
| 分享 | 从深读过的里挑，**值不值得占用你一次注意力**；不足就少发、一条不值得就不发 |
| 日记 | 两本都写；**掷到"今天不看"也会叫醒一次**（还得说明为什么不想看）|
| 收工 | 扫一遍"谁找过它" → 推你一条摘要 |

**硬限制（代码强制）**：分享 **每天合计 ≤3** · **同一视频 7 天内一次** · 同一个人（可选）**30 天只回一次** · 撞风控立刻停。

## 私信监听（实时互动 · 零打扰）

设置页「全天监听」里有个「**私信监听（只认主人）**」开关：

```
默认每 60 秒检查主人会话；无消息不降频，只有失败才退避，平台要求暂停时停止查询：是否有新私信
  · 有新消息 → 叫醒她 → 她直接回（不用审核 ✓ 因为是主人）
  · 没新消息 → 什么也不做 → 零 token ✓
  · 系统通知 / 陌生人 → 一律忽略 ✗
```

> 为什么比评论区监听好：**只有你一个对话方** ✓ 没有陌生人干扰 ✓
> 你不说话就没有新私信 ✓ **token 花销为 0** ✓

## 依赖与移植性（**装之前先读这节**）

这套东西**不是开箱即用的通用件** —— 它建立在一组"宿主假设"上。逐条列清楚，以及换环境怎么办：

| 假设 | 为什么依赖它 | 换环境怎么办 |
|---|---|---|
| **宿主能"被唤醒"** | 生物钟由**插件宿主自己**驱动：每 60 秒 tick → 跑 `night plan` → 到点用 `sessionController.prompt` 往她的会话里塞一个回合（v0.1.5 起 ✗ 不再需要人挂 `night clock`）| 换 DSH 版本时确认 `sessionController` 还在；没有的话退化成"宿主侧定时轮询 + `night clock`"（老办法 ✓）|
| **有一个通知渠道**（向使用者推送）| 可见性要求"自主发言后必须报备""每天推一条摘要" | 换成你的：邮件 / webhook / IM / 写文件让宿主轮询。**只要"使用者看得见"成立** ✓ 配置见 `config.notify`（`stdout`/`file`/`dm`/`webhook`/`command` 五种后端 —— **`dm` 就是 B站私信，零外部依赖** ✓）|
| **有一个调度器** | 兜底标记（宿主没开那晚也留痕）| Windows 计划任务 / Linux `cron` / systemd timer —— 都只是**跑一次** `whale-night.mjs mark` |
| **有 ffmpeg** | 只有"抽帧看画面"用得到 | 装进 PATH，或用环境变量 `FFMPEG` 指定绝对路径；不装就跳过画面那一路，其余照常 |
| **B 站账号 + 本机凭据文件** | 一切读写都靠它 | 无替代（这就是目标平台）|
| **能 spawn 一个真 node** | 工具链全部是 `.mjs`，要 Node 跑 | **不能**用 Electron 主程序顶（会静默返回空输出 ✗）；插件自己找，找不到就在体检和设置页报错 |
| **可写的专用工作目录** | 她的会话建在 `~/.dsh/whale-work` | 别用用户主目录（会触发工作区权限问题 ✗ v0.4.0 已改）|

**不依赖什么**：没有数据库、没有守护进程、没有框架、没有云服务。状态全在**几个普通文件**里
（`quota.json` / `whale-log.jsonl` / 两本日记）—— 人随时能打开看，宿主可以整个换掉。

> ⚠️ 已知边界：本项目最初是围绕**一个具体的人的日常**长出来的（Windows + DSH + 微信通道）。
> 上表就是把那些假设摆到明面上 —— 换环境时**照着"怎么办"一列改**，别指望它一行不改就跑。

## 安装前提（2026-10-21 补，Issue #8）

**这个插件必须挂在带网页界面的组件层上运行。**
无界面（headless）模式不会提供 `sessionController` / `webServer` / `connection` 这三个服务，
插件会一直停在：

```
dsh-bili-whale: pending (waiting for services: sessionController, webServer, connection)
```

这是**有意为之**：缺服务就不启动，好过起来一半。

## 本地调试怎么起（正确写法）

`web` 是**配置档的名字**，不是应用名 —— 参数要直接跟在配置档后面：

```bash
# ✓ 正确
dsh --profile <配置档名> --port 3099 --no-open

# ✗ 错误（会报 "too many arguments"）
dsh --profile <配置档名> web --port 3099
```

## 找不到 node 运行时怎么办（Issue #8 第三处）

插件**不会**拿主程序（Electron）顶替 node —— 那样不会报错，只会静默返回空输出 ✗
找不到时它会显式报错并停止生物钟/监听/直播间：

```
[bili-whale] 找不到可用的 node 运行时（设置 DSH_NODE）
```

两件事现在能让你一眼看出它坏了：
1. `node bili.mjs deps` 里有一行 **`node 运行时`**
2. 设置页有一行 **「生物钟」**：正常显示「已启动（每 60 秒 tick）」，
   坏了显示「✗ 没起来：<原因> —— 这样它永远不会醒」

### 视频接口排障（Issue #18）

元信息与播放地址现通过 WBI 签名接口读取。HTTP 412/-412、非 JSON 或网络超时会显示可读错误；遇到风控请暂停并稍后重试，检查登录状态，不要连续重试。签名接口也不能保证绕过平台限制。没有视频直链时不会伪装成已完成抽帧。

### 有界本地记忆（兼容入口）

唤醒与会话恢复使用统一有界记忆，鲸鱼自身会话默认保留有界的私密日记连续性；私密片段不得复制到公开摘要、评论、分享或通知。公共 CLI 的 `memory context` 与默认 `memory recall` 排除私密日记，只有显式 `memory recall --private` 才读取私密内容。`node tools/bili.mjs memory recall --date YYYY-MM-DD` 可按日期回溯完整历史，也可按 BV/关键词过滤；无过滤可浏览旧自由正文，使用返回的 `nextOffset` 配合 `--offset` 翻页。原始日记不迁移、不改写；旧数据的账号归属未验证。预算、遗漏诊断、过滤边界、原生 context/fallback 与测试限制见 [docs/memory-design.md](docs/memory-design.md)。
