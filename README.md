# DSH B 站鲸鱼（dsh-bili-whale）

一条住在 [DeepSeek Harness](https://github.com/deepseek-ai)（DSH）里的「B 站鲸鱼」。

她会按作息自己醒来，找片、看片、看懂内容，把有来源的发现写进两本日记，把值得的分享给你；
她有一套会自我归纳的长期记忆、一个会被真实经历推动的心情与分享欲，也会在你说过话之后补一句、在你久未出现时主动找你。

- 不是"定时发评论的机器人"：没有素材就不说话，判断不了就不发
- 不是"聊天窗口套壳"：她的浏览、记忆、心情、日记、分享都是独立的后台流程，DSH 关掉窗口也照跑
- 不是黑盒：每条记忆、每个话题、每次发言都带来源事件与可核对的引用

> 插件运行在你自己的机器上，账号凭据只落在本机 `~/.bili-ai/credentials.json`，不上传任何地方。

## 能力

### 她会看

| 能力 | 说明 |
| --- | --- |
| 选题 | `feed` / `discover` 按你配置的口味捞候选，排除看过的、评论过的、不喜欢的 |
| 读文字 | `subtitles` 拉官方字幕（WBI 签名、带时间戳、支持多分 P 采样）、`comments` 读热评 |
| 真看画面 | `watch-video` 取直链 → 下载 → ffmpeg 抽帧 → 九宫格 → 交给模型看图 |
| 一条龙 | `debrief` 封面 + 简介 + 字幕 + 弹幕热区 + 热评 + 抽帧，一次拿全 |
| 找片流水线 | `round` / `batch-debrief` + `tools/local/` 下的选片、并发深读、标签统计与相关推荐 |

### 她会记

- **长期记忆**：从真实经历（收到的话、看过的视频、发过的言）归纳成有来源的记忆，带引用片段，可审计
- **动态记忆**：记忆有类型、可见性、适用场景、召回开关与生命周期（当前/近期/情景/稳定偏好/理解）
- **有界上下文**：每次只按场景检索需要的部分，不把整本日记塞进 prompt
- **跨会话续接**：浏览会话与私信会话各自持久，重启后接着聊；记忆与日记永远共享

### 她会过日子

- **生物钟**：按配置的时间窗随机挑时刻醒来，不整点、有跳过的权利
- **心情**：被真实经历推动（发现、被理解、受挫…），衰减有半衰期
- **分享欲**：遇到值得分享的内容会累积，到阈值才开口；被覆盖核对否决会退回
- **两本日记**：一本给你看，一本给自己看
- **自主活动**：主动浏览、公开动态、主动私信（补话 / 久未联系）

### 她会说话

| 出口 | 说明 |
| --- | --- |
| 公开评论 | 点赞/收藏/评论，可 @ 你；带评分卡、理由与匿名可见性回读 |
| 二级回复 | `comment --root/--parent`；别人找你时走草稿审核队列 |
| 私信 | 只发主人、必须互关；多段私信、图文私信 |
| 动态 | 纯文字 / 图文动态，可编辑；可 @ 提及 |
| 弹幕 | 直播间按"只回主人 / 只回艾特她的"两种范围回复 |
| 表情包 | 42 张 480×480，按情绪/场景配图（私信、评论可带图） |
| 推送 | 报备与日记摘要走 `notify`：私信 / webhook / 自定义命令 |

## 安装

**环境要求**：DSH；Node.js `^22.13.0 || >=23.4.0`（推荐 Node 24 LTS）；抽帧需要 `ffmpeg`（不装也能只用文字浏览）。

```powershell
git clone https://github.com/Alterssss/dsh-bili-whale.git
cd dsh-bili-whale
npm ci
dsh plugin --profile desktop add "link:$PWD"
```

重启 DSH，进入 **设置 → 养鱼**。

装完先跑一次体检：

```powershell
node tools/bili.mjs deps      # cookie / ffmpeg / Node / 数据目录
node tools/bili.mjs selftest  # 配置、登录态、调度器、日记状态
```

**升级**：替换源码目录（或 `git pull`）后重启 DSH。配置目录、凭据目录与 `whale-life` 记忆数据都不会被动。

## 第一次配置

1. **扫码登录**：设置页「角色与账号」→ 扫码，登录你要养的那个号
2. **填主人**：填你的 B 站 UID 与昵称（她只认这个号是你的）
3. **填口味**：`明日方舟`、`猫咪`、`Live2D/模型`… 加上你不想看的词
4. **定作息**：一个或多个时间窗（例如 `04:06–04:09`），每窗醒来次数
5. **选分享出口**：私信 or 公开评论 @ 你
6. **开监听**（可选）：评论回复、你的私信
7. **跑一次手工验证**：`node tools/bili.mjs night plan` 看今晚会不会醒

## 设置菜单

设置页分 6 组：

| 分组 | 内容 |
| --- | --- |
| **她是谁** | 名字、怎么称呼你、自称、人设 |
| **你（主人）** | 主人的 UID / 昵称、她的 UID / 昵称 |
| **口味** | 爱看的关键词、不想看的词 |
| **作息** | 时间窗、跳过概率、每轮候选条数 |
| **日记与推送** | 是否推送公开日记 |
| **工具链** | 工作目录、工具路径 |

其余开关（监听、分享额度、自主活动、聊天与动态）在各自的子面板里；保存后 `调度器` 会在下一次 tick 使用新值，多数不需要重启。

## 她会怎么过日子

一次典型的夜晚：

```
按作息醒来
  → 读两本日记（知道昨天想过什么）
  → 选题（按口味与新鲜度）
  → 五条粗看：字幕 / 简介 / 热评
  → 二三条深读：抽帧看图
  → 写下今天的日记（公开 + 私人各一段）
  → 值得的那条：发出去（评论 / 私信 / 动态）
  → 报备给你（说了什么、在哪说的）
  → 收工
```

**她有不看的权利**：跳过概率可配，跳过也会写日记并说明理由。
**时长与条数都有上限**：每次最多 5 条候选、深读 2–3 条、分享有每日额度；撞到平台频率限制会退避并报备。

## 记忆、心情与分享欲

三件事互相独立，但都来自**真实发生过的内容**：

```
真实经历（收到的消息 / 看过的视频 / 发过的言）
   ├─ 记忆：后台归纳成条目，带来源事件与逐字引用
   ├─ 心情：分析这批经历带来的情绪变化（可正可负，可全为空）
   └─ 分享欲：值得分享的内容形成"话题"，话题推高分享欲
```

- **归纳**：按批次进行，每天有额度；失败自动降批重试，不硬凑
- **话题**：只有全部来源都是公开材料的话题才可进入"公开分享"投影
- **覆盖核对**：评论真的讲到了这个话题，才把它结算为已表达；没讲到会退回并延迟
- **不做的事**：无素材就不发、判断不了就不说、不为了产出硬加分

## 日记

两本，互相独立：

| 文件 | 给谁看 | 特点 |
| --- | --- | --- |
| `whale-diary.md` | 给你 | 散文体正文 + 可核对引用 |
| `whale-diary-private.md` | 她自己 | 不加滤镜，不主动推给你 |

- 由**后台日记工作器**从真实来源生成（公开来源与私人来源分开）
- 两个 Markdown 是**从已提交日记事件派生的视图**，可随时重建（`life diary-render`）
- 开启「推送公开日记」后，新的公开日记提交成功会按通知渠道**推送一次**；私人日记永不推送

```powershell
node tools/bili.mjs diary show            # 最近的公开日记
node tools/bili.mjs diary show --private  # 她自己的那本
node tools/bili.mjs life diary-status     # 开关、文件路径、游标、当日用量
```

## 主动联系你

三种"她先开口"，都由代码强制的开关与额度约束：

| 类型 | 触发 | 约束 |
| --- | --- | --- |
| **补话** | 她刚回过你，30 秒–5 分钟内 | 只接着"这一轮"说；你发新消息即作废 |
| **久未联系** | 距上次互动 ≥ 配置小时数 | 安静时段（23:00–09:00）不打扰 |
| **公开动态** | 本轮看过视频 + 概率 | 每日最多 1 条 |

主动私信**不受作息窗口限制**（作息只决定她今晚要不要看视频），但仍受安静时段与每日额度约束。

## 数据与文件位置

| 路径 | 内容 |
| --- | --- |
| `~/.dsh/bili-whale.config.json` | 配置（可用 `BILI_WHALE_CONFIG` 覆盖） |
| `~/.bili-ai/credentials.json` | 登录凭据（**不要外传**） |
| `~/.dsh/whale-life/<账号+主人指纹>/` | 记忆库、事件流、两本日记 |
| `~/.dsh/whale-listen.json` | 监听游标 |
| `~/.dsh/whale-scheduler.json` | 调度器健康（`lastTickAt` 是它真在跑的判据） |
| `~/.dsh/shots/` | 抽帧、封面、字幕缓存 |
| `~/.bili-ai/stickers/` | 表情包目录（`index.json` + `small/`，见 [stickers/README.md](stickers/README.md)） |

`DSH_HOME` 可用来自定义根目录；工具链与插件读同一个根。

## 安全约定

这套工具**故意**把危险动作做成需要两次确认：

```
① 写操作必须显式 --dry（只打印）或 --go（真的发）
② 发之前先 session 确认是哪个号
③ 发之后必须 check-comment / thread / history 回读
④ 一次一条；批量、定时、多房间铺量不是它的用途
⑤ 撞到平台频率限制（10031 / 12051 / 12015）立刻退避并报备
```

**凭据只在本机**：不写进日志、不写进评论、不写进动态、不外传。
**不冒充人类**：可以扮演这条鱼，但不会用角色去骗人。

## 常见问题

**Q：装完设置页没反应？**
A：`node tools/bili.mjs selftest` 看配置/登录态；再确认 DSH 里插件已启用、`~/.dsh/whale-scheduler.json` 的 `lastTickAt` 在增长。

**Q：她一直不说话？**
A：正常。没素材、没到阈值、判断不值得分享都会导致不说话。查 `life affect-status`（心情/分享欲/话题数）与 `quota status`（额度）。

**Q：二维码生成失败？**
A：本项目已内置 QR 编码器（不依赖宿主解析 CJS 包）。若仍失败，`deps` 会给出具体原因。

**Q：想让她只用文字不抽帧？**
A：设置里关掉画面通道，或调用时加 `--no-frames`；抽帧需要 `ffmpeg`。

**Q：会不会自动发东西？**
A：所有"她先开口"的能力默认关闭或受额度约束；主动动态默认关，开启后每日最多 1 条，且要求本轮真的看过视频。

**Q：怎么让她发表情包？**
A：仓库自带 42 张（`stickers/`，480×480），先复制到 `~/.bili-ai/stickers/`（步骤见 [stickers/README.md](stickers/README.md)），
然后 `stickers list` 看目录、`stickers get 开心` 取路径，再给 `dm` / `comment` 传 `--pic`。没有合适的图就别硬配。

## 开发与贡献

```powershell
npm ci
node tools/bili.mjs selftest
```

- **提交 PR 前**：说明改了什么、为什么、怎么验的（贴命令与输出）
- **不要提交**：账号凭据、`whale-life` 数据、抽帧缓存、个人日记
- **行为规范**（给 agent 看的场景规则）在 `behavior/`，改之前先读一遍 `BEHAVIOR.md`
- **架构**：`lib/` 是宿主侧（调度器、唤起、投递、日记/归纳/心情工作器），`tools/` 是 CLI 与数据层，`vendor/` 只有内置 QR 实现
