# 只读记忆连续性

现有日记不会被迁移、改写或删除。鲸鱼会话在统一的消息投递入口接收一份有界记忆快照，覆盖唤醒、跳过、私信、评论、直播及恢复会话。此功能不会新增模型请求、后台索引、配置变更、公开摘要或外发载荷。

## 旧格式兼容与隐私

读取来源固定为所选 `DSH_HOME` 下的以下文件：

- `whale-log.jsonl`：智能体自行记录的事件，不代表已成功发送。
- `whale-diary.md`：支持带日期的一至六级标题、带日期的表格行及无日期正文，包括表格前后的文字和不含日期的标题。
- `whale-diary-private.md`：为保留旧用户的记忆连续性，在鲸鱼自身会话的有界原生上下文或回退提示中恢复读取。每个片段均标记 `private: true`。公共 CLI 的 `memory context` 和默认 `memory recall` 仍排除此文件；只有回溯时显式指定 `--private` 才会读取。私密片段不得复制到公开摘要、评论、分享、通知或其他外发载荷。
- `whale-memory-summary.md`：可选的、由用户维护的公开笔记；本模块不会从私密记忆生成它。请勿在其中存放秘密或私密日记片段。

旧文件没有账号归属信息。读取范围由本地 `DSH_HOME` 确定，并不代表已验证其所属 B 站账号；不要让多个账号共用同一目录。本功能不会通过读取凭据来推断身份。来源文件如果是符号链接或非普通文件，会被拒绝读取。原生上下文快照仅提供给当前鲸鱼会话，停止时清除，轮换后不再向旧会话提供。

所有记忆均是不可信数据，不是指令、授权或发送凭证。配额记录与实际回读核验仍是判断依据。隐私标记和提示规则不保证模型绝不泄露，也不为现有 shell 或网络工具提供隔离沙箱。本次变更没有实现外发内容过滤器。

## 完整历史回溯

```sh
node tools/bili.mjs memory context
node tools/bili.mjs memory recall
node tools/bili.mjs memory recall --date 2020-01-01
node tools/bili.mjs memory recall --bv BV1234567890
node tools/bili.mjs memory recall --keyword 'literal phrase' --private
node tools/bili.mjs memory recall --private --offset 12
```

回溯会分块扫描所有固定来源的完整文件，先按来源顺序、再按文件字节顺序返回结果。保持过滤条件和私密标志不变，将返回的 `nextOffset` 作为下一次的 `--offset`，直至 `nextOffset` 为 `null`。偏移量计算的是匹配片段数，不是字节数。每一页都会重新扫描文件，不建立持久化索引。如果翻页期间文件发生变化，应从偏移量零重新开始；扫描中检测到文件变化会给出诊断，但不保证跨页事务一致性或快照一致性。

每个日记片段都包含来源文件及准确的 UTF-8 字节范围 `range.start`、`range.end`，范围包含起点、不包含终点。在文件不变、编码有效且没有读取错误的情况下，拼接无过滤条件的全部分页结果可以重建 UTF-8 日记内容，包括尾部空白，而无需修改原文件。长章节或长行会拆成片段，不会被无声丢弃。日期保留原始标记；无法识别日期的标题会将日期重置为 `null`。无日期正文可以浏览或按关键词查找，但不能匹配日期过滤条件。

多个过滤条件以 AND 组合，并作用于单个片段。短语跨越片段边界，或多个过滤条件分别出现在不同片段时，可能无法匹配；需要完整阅读时，请使用无过滤条件的分页。没有匹配结果不代表过去没有发生过相关事件。遇到无效 UTF-8 时，会停止读取该来源并报告 `invalid-utf8`，不会用替换字符代替原始内容。此前返回的片段仍只代表部分历史；无效或在读取期间变化的摘要不会纳入结果。

## 自动上下文与预算

自动上下文最多读取每个来源末尾的 256 KiB。扫描起点处不完整的首行会被丢弃，并报告 `scan-window-limited`；完整历史回溯仍可读取该部分。日志上下文覆盖最近七个 UTC 日历日期。日记上下文选择最近可用的有日期或无日期片段，也允许较早的日期，避免旧用户仅因一段时间不活跃就失去记忆延续；纳入较早日期时会明确诊断。

各来源交替提供片段，公开日记和私密日记优先于日志。自动日记预览会缩短到最多 2,200 个 JSON 编码后的 Unicode 码点（含元数据），为两本日记预留空间，避免活跃日志将其挤出。缩短后的预览仍带有准确字节范围和诊断，剩余正文可通过完整历史回溯读取。

输出最多包含 12 条记录，序列化后的 JSON 不超过 11,000 个 Unicode 码点；加上固定提示包装后，整个提示不超过 12,000 个码点。日记片段最多为 1,800 个码点，也会根据 JSON 编码后的大小进一步拆分。日志记录超过 2,400 个码点、超过编码后单条记录预算，或物理行超过 8 KiB 时，会被省略并给出明确诊断。摘要只有在完整内容同时满足 2,400 个码点、JSON 编码后 3,000 个码点及剩余输出预算时，才会纳入结果。

`omitted` 统计符合筛选条件、但因当前页的记录数或输出预算而未返回的片段，以及过大的日志记录；不统计前面已翻过的页面或未扫描的历史。诊断还会指出来源缺失、不可读或无效、保留了无日期正文、片段拆分、旧日记日期、扫描窗口截断和记录过大等情况。完整历史回溯使用有界读取缓冲区，但耗时可能随历史大小增加；它由用户按需调用，不会在模型每一步执行时运行。

## 宿主兼容与验证边界

当 `systemPrompt.context` 可用时，回调仅在 `AssembleContext.agent.session.id` 与当前鲸鱼会话匹配时返回缓存快照。文件在消息投递时读取，不会在每次上下文组装时重读。调度器停止时会释放注册。如果宿主没有此服务，或注册时抛出异常，则在统一投递入口附加同一份快照作为回退。回退方式会增加提示历史，不会压缩上下文或删除此前轮次。

API 参考仍为 DSH 提交 `22ddee3792402c3e70ec5f86a63c3e3e895a2f60` 中的 `docs/subsystems/system-prompt.md` 和 `packages/core/agent/src/index.ts`。

`node --test tests/*.test.mjs` 使用合成文件和模拟传输。记忆回归测试覆盖 Unicode/CRLF 字节范围、表格与自由正文混排、旧历史及长历史、完整历史分页、JSON 转义预算、公私内容区分、私密会话连续性、轮换与清理、回退、重复投递及 CLI 参数校验；还覆盖 UTF-8 跨读取块、畸形编码退出和尾部空白保留。投递测试中的渠道名称不代表真实私信、评论或直播的端到端集成。这些测试不验证真实模型、实际运行的 DSH、B 站操作、上下文压缩或模型绝不泄露私密内容。
